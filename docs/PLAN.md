更新日期：2026-11-07

## 已确认目标

- 用户：需要在手机上发现附近洗浴、足疗、私汤和大众澡堂的访客，以及维护门店资料的管理员。
- 核心结果：保留现有地图发现、定位降级、半径/分类筛选、站长推荐、详情、图片、评价、收藏/账户和后台维护能力。
- 前端：React 19 + React Router Framework Mode + Vite + TypeScript + Tailwind CSS 4 + HeroUI v3 + Motion + Lucide React + TanStack Query。
- 后端：Rust + Axum + Tokio + SQLx，数据库迁移到 PostgreSQL；保留现有 JSON API 路径和响应兼容性，完成后才切换写入。
- 发布：本机完整验收后部署到现网 `/washjoy/`，保留旧前端产物、SQLite 快照和 PostgreSQL 回滚材料。
- 设备：移动端优先，覆盖 390×844 与桌面；PWA manifest、Service Worker、安全区和深链接必须保留。

## 非目标

- 沿用已验证的 React Router SSR；不引入 Redis、独立队列或微服务。
- 不改变门店、评价、账户和管理员的业务权限；不删除原始 SQLite 数据。
- 不引入第二套完整 UI 组件库；HeroUI v3 为唯一主组件体系。

## 数据与兼容

旧表映射：`users`、`sessions`、`reg_limit`、`login_fail`、`store_overrides`、`reviews`。
PostgreSQL 使用带时区时间、参数化 SQL、软删除和最小权限角色。导入工具必须可重复执行，按主键/自然键幂等，导入前后核对记录数、管理员角色、门店覆盖、评价和图片 URL。

匿名访客与已登录用户继续使用 HttpOnly、Secure、SameSite Cookie。管理员接口保留 Origin/CSRF、资源授权、审计和失败限流边界。浏览器不接触数据库连接串、OSS 密钥或地图服务端密钥。

## UI 与 API 契约

- 保持 `/washjoy/`、`/washjoy/account/`、`/washjoy/mine/`、`/washjoy/admin/` 深链接。
- API 统一迁移到 `/api/v1/` 的内部契约适配层，同时兼容现有 `/api/*` 公网路径；错误包含 `code`、`message`、`requestId`。
- 首页首屏最多 30 家，分页稳定去重；地图按需加载，路线查询具备超时、缓存和降级。
- 所有页面覆盖加载、空、错误、成功、权限拒绝、长文本、键盘、窄屏、深色和 reduced-motion。

## 发布与回滚

1. 本机冻结安装、typecheck、lint、单元/API/浏览器测试、Rust fmt/clippy/test/release build。
2. 备份 SQLite、门店 JSON、图片引用和现有 `.output`；创建 PostgreSQL 数据库、角色、迁移和脱敏恢复验证。
3. 先部署兼容 API 与新前端到独立 release，健康检查和公网 smoke 通过后切换 `current`/服务。
4. 观察 API 错误率、登录、门店查询、图片、地图、后台写入和资源；失败立即切回旧前端/API，数据库按独立恢复方案处理。

无。若迁移过程中发现字段无法无损映射，先停在当前切片并记录阻塞，不静默丢弃数据。
